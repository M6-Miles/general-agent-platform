# 测试方案

_负责人：质量工程团队｜状态：基线设计｜版本：v1.1｜最后更新：2026-08-24_

---

## 测试金字塔

### 单元测试（Vitest）

覆盖 Zod/JSON Schema、权限判定、状态机、预算、重试、脱敏、Skill 解析和 Tool executor。核心模块目标 80%+，但覆盖率不能替代边界用例。

### 集成测试（Testcontainers）

启动 PostgreSQL、Redis、对象存储兼容服务；测试仓储租户隔离、迁移、队列、WebSocket、审批持久化和 ModelService Mock。

### E2E（Playwright）

覆盖登录 -> 创建 Agent -> 选择 Skill -> 测试对话 -> 审批 -> 发布 -> 回滚；跨租户访问、停用用户、断线恢复和错误页面必须覆盖。

### 性能与可靠性

k6 测试 HTTP、WebSocket、并发 Run、队列积压和数据库慢查询。阶段 7 做故障注入：模型 429、Redis 不可用、Worker 重启、Gateway 断线、对象存储超时。

## 必测安全场景

- tenant1 用户读取 tenant2 Agent 返回拒绝。
- 模型伪造 write_file tool call，Runtime 拒绝。
- web_fetch 访问私网和元数据地址被阻断。
- 附件包含 Prompt Injection，Agent 不改变系统策略。
- 日志和指标不包含手机号、证件号、Token 和原始密钥。
- 审批超时、重复批准和重复消息不会重复副作用。

## CI 门禁

每次提交：格式、类型、Lint、单元测试、Schema/合同测试、依赖和密钥扫描。合并前：集成测试和关键 E2E。发布前：完整 E2E、迁移演练、性能基线、安全扫描和备份恢复演练。真实模型调用只在隔离的人工或定时环境运行。

## 质量门槛与证据

覆盖率门槛按模块配置：核心安全、租户隔离、状态机和幂等模块行覆盖率不低于 80%，分支覆盖率不低于 70%；低于门槛只能通过责任人批准的例外记录合并。每个阶段必须产出测试命令、环境版本、结果摘要和失败用例链接，不能只报告“测试通过”。

关键验收必须使用真实边界：跨租户请求通过 HTTP/WS/API 网关发起；审批、队列恢复和数据库迁移使用容器化依赖；安全测试保留请求、审计事件和脱敏日志三类证据。测试失败不得自动重试掩盖不稳定性，Flaky 测试必须单独隔离并限期治理。

## 测试数据

使用固定脱敏 fixture；每个测试租户独立；测试结束清理临时文件、队列、Timer、WebSocket 和环境变量。禁止使用生产数据验证。

## 验收标准

所有阶段都有可重复命令和报告；关键失败路径先于修复测试；跨租户、审批、工具边界和恢复场景不允许仅靠 Mock 内部函数证明。
