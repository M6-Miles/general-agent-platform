# 一个月 MVP 范围与排除项

_负责人：项目负责人｜状态：范围冻结｜版本：v1.0｜最后更新：2026-08-24_

## 项目定位

本项目交付一个面向多租户、工具调用和工作流执行的可审计 Agent Runtime 企业级研究型工程原型。目标是证明关键运行时语义可以运行、恢复、审计和测试，不承诺达到生产交易系统或完整 SaaS 平台的容量等级。

## 本月必须交付

| 能力 | 必须交付的可验证结果 |
|---|---|
| 工程基础 | Docker Compose 可启动 API、Worker、PostgreSQL、Redis；`.env.example` 完整；健康检查可用 |
| 身份与多租户 | 登录/注销、租户上下文、三类角色（platform_admin、tenant_admin、member）、跨租户访问返回 404 |
| Agent | 草稿创建/编辑、发布不可变版本、版本查询；Run 绑定发布版本快照 |
| Tool | ToolDefinition 注册、JSON Schema 输入输出校验、能力 allowlist、超时和有限重试 |
| Run | 异步创建、状态机、取消、预算检查、attempt、checkpoint、恢复和终态审计 |
| Workflow | 最小 DAG：prepare -> model -> tool -> finalize；支持条件分支和失败终止 |
| 审批 | 高风险 Tool 进入 waiting_approval；批准/拒绝一次性生效并记录审计 |
| 审计 | 追加写入 Run、Tool、审批、权限拒绝和配置变更事件；按租户分页查询 |
| 模型 | MockProvider 必须可运行；真实模型 Provider 通过环境变量启用且失败可观测 |
| 接口 | `openapi.yaml`、JSON Schema、统一错误码、幂等键、cursor 分页 |
| 质量 | 单元、集成、API 合同和至少一条 Playwright 主链路测试；CI 执行静态检查和测试 |
| 交付 | Docker 部署说明、架构图、ADR、测试证据、已知限制和演示脚本 |

## 演示主链路

```text
登录 -> 创建 Agent 草稿 -> 注册/选择 Tool -> 发布版本
  -> 创建 Run -> Harness 校验 -> 自动 Tool 或审批
  -> checkpoint 持久化 -> 完成/失败 -> 查询结果和审计
```

## 角色系统（已实现）

- `admin`：平台管理员，等同于原设计中的 `platform_admin`
- `tenant_admin`：租户管理员
- `member`：普通成员
- `readonly`：只读用户，属于超出原冻结范围的安全增强

## 明确排除项

以下能力本月不进入交付验收，只保留接口或演进设计：

- Kubernetes、多地域部署、服务网格和微服务拆分
- 真实券商连接、真实订单提交、支付和计费
- 知识库/RAG、渠道接入、插件市场和复杂工作流设计器
- 多模型智能路由、模型微调和大规模训练
- 完整分布式调度、跨地域灾备和无限水平扩展
- 生产级合规认证、渗透测试认证和正式 SLA 承诺

## 完成定义

MVP 只有在以下条件同时满足时才算完成：关键主链路可在全新环境启动；数据库迁移可前向执行并在测试库回滚；跨租户、越权、重复幂等键和审批重复提交测试通过；Run 终态与审计事件可查询；CI 保存测试和契约校验结果。未满足的企业级能力必须列入限制清单，不得以文档描述替代实现证据。
